# Host relay lifetime change for long browser dictation

Source review, 2026-09-29. Active prepared OpenClaw 2026.9.6 tree is commit [`d30287734dee7ab3d86b216777c11ea195a021b8`](https://github.com/openclaw/openclaw/tree/d30287734dee7ab3d86b216777c11ea195a021b8). This is a design recommendation only: no host/plugin code or live configuration was changed.

## Finding

The Gateway transcription relay fixes `TRANSCRIPTION_SESSION_TTL_MS` at 30 minutes. It computes `expiresAt` when `talk.session.create` runs and arms a timer for that same duration. Append and close requests reject expired sessions via `requireActiveTalkRelaySession`. Timer expiry or lazy expiry closes the provider with reason `completed`, deleting the relay before any provider final-drain; later `onTranscript` callbacks are ignored because `getActiveRelay` no longer finds it. This can silently lose the whole final-only transcript. The stock composer ignores `close/completed` while recording; its next failed append produces an error and invokes Stop, but by then the provider has been torn down. [Relay source](https://github.com/openclaw/openclaw/blob/d30287734dee7ab3d86b216777c11ea195a021b8/src/gateway/talk/transcription-relay.ts#L34-L50), [create/timer](https://github.com/openclaw/openclaw/blob/d30287734dee7ab3d86b216777c11ea195a021b8/src/gateway/talk/transcription-relay.ts#L258-L420), [expiry check](https://github.com/openclaw/openclaw/blob/d30287734dee7ab3d86b216777c11ea195a021b8/src/gateway/talk/relay-session-lifecycle.ts#L70-L93), [composer handling](https://github.com/openclaw/openclaw/blob/d30287734dee7ab3d86b216777c11ea195a021b8/ui/src/pages/chat/composer-dictation.ts#L255-L318).

This is host-owned, not a plugin option. The public provider contract has only `connect`, synchronous `sendAudio`, `close`, `isConnected` and callbacks; no TTL renewal or session transfer. The browser holds one session ID until Stop. Existing `talk` config is a strict schema with no transcription lifetime setting, and the relay never reads a duration from runtime config. A plugin configuration field cannot override this. [Provider interface](https://github.com/openclaw/openclaw/blob/d30287734dee7ab3d86b216777c11ea195a021b8/src/realtime-transcription/provider-types.ts#L20-L40), [Talk schema](https://github.com/openclaw/openclaw/blob/d30287734dee7ab3d86b216777c11ea195a021b8/src/config/zod-schema.root-support.ts#L198-L270), [composer create](https://github.com/openclaw/openclaw/blob/d30287734dee7ab3d86b216777c11ea195a021b8/ui/src/pages/chat/composer-dictation.ts#L139-L185).

## Smallest upstream change

Prefer a **targeted fixed host default**, not a new config surface for one local use case: raise the transcription-only relay TTL to a value just beyond 60 minutes (for example 65 minutes). Do not change the separate realtime Talk relay TTL. A 60-minute timer beginning at session creation does **not** guarantee a 60-minute recording: microphone capture starts before creation, and Stop at the deadline must still send queued frames and allow the provider's five-second final drain. The 65-minute internal relay guard is headroom, not an advertised 65-minute recording promise. The plugin/browser should impose the requested 60-minute recording ceiling and stop/finalize gracefully before that guard. If upstream wants user-selectable durations, a validated transcription-specific config field could be proposed later, but it requires schema/types/metadata, runtime wiring, documentation, validation and tests; `talk.realtime.*` and voice-call provider options are not an existing TTL knob. [Separate Talk TTL](https://github.com/openclaw/openclaw/blob/d30287734dee7ab3d86b216777c11ea195a021b8/src/gateway/talk/relay/state.ts#L24), [transcription stop/drain](https://github.com/openclaw/openclaw/blob/d30287734dee7ab3d86b216777c11ea195a021b8/src/gateway/talk/transcription-relay.ts#L465-L505).

**Important qualification:** a bare constant change is necessary to exceed 30 minutes but is insufficient for a truthful 60-minute/no-silent-loss release. Add expiry handling that first runs a bounded graceful provider `close()` and keeps the relay registered for the existing five-second final-drain window, emits an explicit timeout/error to the owner if an unexpected hard expiry occurs, and avoids labeling lost audio as successful `completed`. The browser should handle a terminal close/timeout while still recording and preserve or insert the last confirmed final; with final-only plugin output, it must wait for the final before tearing down. An earlier browser-side 60-minute timer should stop capture and call `talk.session.close` before the host guard, surfacing a clear limit message. Preserve session ownership and the existing `onTranscript` late-final routing. Do not claim that an error label alone recovers undelivered audio. These are bounded host/UI changes, separate from the simple TTL constant; they require focused integration tests. [Close implementation](https://github.com/openclaw/openclaw/blob/d30287734dee7ab3d86b216777c11ea195a021b8/src/gateway/talk/transcription-relay.ts#L185-L213), [provider drain](https://github.com/openclaw/openclaw/blob/d30287734dee7ab3d86b216777c11ea195a021b8/src/gateway/talk/transcription-relay.ts#L465-L505), [composer Stop snapshot](https://github.com/openclaw/openclaw/blob/d30287734dee7ab3d86b216777c11ea195a021b8/ui/src/pages/chat/composer-dictation.ts#L659-L707).

## Tests and rollout implications

- Relay fake-clock tests: `expiresAt` and timer agree; active at 30+ minutes; Stop near the 60-minute recording boundary drains final within five seconds; hard expiry produces visible interruption and accepts a late final during drain; owner disconnect still closes immediately; wrong-connection append/close still fail; Date-range overflow still rejects. Existing relay tests already cover graceful drain and Date overflow but not the 30-minute expiry path. [Relay tests](https://github.com/openclaw/openclaw/blob/d30287734dee7ab3d86b216777c11ea195a021b8/src/gateway/talk/transcription-relay.test.ts#L329-L520).
- Composer tests: auto-Stop/timeout, no silent lost transcript, no duplicate insertion, no stale-session insertion, pending audio fully delivered before close, and final visible/editable without sending to the agent. Note the stock Stop path commits any nonempty snapshot immediately and ignores later corrections, so final-only emission remains required until the composer is fixed. [Composer controller](https://github.com/openclaw/openclaw/blob/d30287734dee7ab3d86b216777c11ea195a021b8/ui/src/pages/chat/composer-dictation.ts#L659-L707).
- Qualification: 20-second rapid iteration; at least one uninterrupted five-minute real-browser/microphone end-to-end test; separately exercise near-boundary 60-minute behavior before advertising that ceiling. The five-minute test cannot prove hour-long stability, browser queue behavior, or recovery. No test result is claimed here.
- Deployment: this is a host source/build change, not installable through the external plugin or `openclaw config`. Replacing the active Gateway build and restarting it would disrupt active sessions; any live rollout requires OG's explicit current-conversation confirmation under workspace `AGENTS.md`, a maintenance window and rollback to the known release. No restart or live change was performed.

## Rollover alternative

Host-supported seamless rollover is **not a small patch**. It would need browser ownership of multiple sequential relay IDs or a new Gateway rebind/renew RPC, exact handoff of queued audio, provider context/partial transcription continuity, final reconciliation without duplicate/missing words, failure recovery, and tests around the boundary. The current public plugin interface cannot replace the browser's session ID or extend `expiresAt`. Prefer a longer bounded host TTL for this release; revisit rollover only if genuine unlimited recordings become a product requirement beyond the 60-minute technical ceiling.
