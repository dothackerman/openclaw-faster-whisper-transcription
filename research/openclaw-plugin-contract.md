## Decision: implement one native realtime-transcription capability

The idiomatic seam is `api.registerRealtimeTranscriptionProvider(...)`, not a new browser UI, Talk transport, Gateway RPC, model provider, generic media-understanding provider, or uploaded-voice-note path. OpenClaw lists realtime transcription as a native plugin capability, and its Talk documentation explicitly uses `talk.session.create({ mode: "transcription", transport: "gateway-relay", brain: "none" })` for captions/dictation. The provider interface is exported from `openclaw/plugin-sdk/realtime-transcription`. [Capability architecture](https://github.com/openclaw/openclaw/blob/d30287734dee7ab3d86b216777c11ea195a021b8/docs/plugins/architecture.md#L32-L45) · [Talk overview](https://github.com/openclaw/openclaw/blob/d30287734dee7ab3d86b216777c11ea195a021b8/docs/nodes/talk.md#L13-L18) · [SDK export](https://github.com/openclaw/openclaw/blob/d30287734dee7ab3d86b216777c11ea195a021b8/src/plugin-sdk/realtime-transcription.ts#L1-L28)

External capability registration is supported but not promised to be frozen; pin a tested `openclaw.compat.pluginApi` floor and use narrow documented SDK subpaths. [Compatibility stance](https://github.com/openclaw/openclaw/blob/d30287734dee7ab3d86b216777c11ea195a021b8/docs/plugins/architecture.md#L61-L77) · [Package compatibility](https://github.com/openclaw/openclaw/blob/d30287734dee7ab3d86b216777c11ea195a021b8/docs/plugins/manifest/package-json.md#L35-L65)

## Provider/session interface

Register an object descriptor with `id`, `label`, `isConfigured`, and `createSession`; optional fields are `aliases`, `defaultModel`, `models`, `autoSelectOrder`, and `resolveConfig`. `createSession` is synchronous and returns `{connect(): Promise<void>, sendAudio(audio: Buffer): void, close(): void, isConnected(): boolean}`. Creation receives `cfg?`, `providerConfig`, and callbacks `onPartial`, `onTranscript`, `onSpeechStart`, `onError`. Factories are also allowed, but must return synchronously and should not start sessions or read credentials during descriptor construction. [Provider type](https://github.com/openclaw/openclaw/blob/d30287734dee7ab3d86b216777c11ea195a021b8/src/plugins/capability-provider.types.ts#L459-L473) · [Session type](https://github.com/openclaw/openclaw/blob/d30287734dee7ab3d86b216777c11ea195a021b8/src/realtime-transcription/provider-types.ts#L1-L40) · [Factory guidance](https://github.com/openclaw/openclaw/blob/d30287734dee7ab3d86b216777c11ea195a021b8/docs/plugins/sdk-entrypoints/native-providers.md#L15-L42)

The documented shared WebSocket helper is for an upstream WebSocket service. A local Faster-Whisper worker can implement the same session interface directly; inventing a WebSocket hop solely to call that helper is unnecessary (inference). [Voice/audio guidance](https://github.com/openclaw/openclaw/blob/d30287734dee7ab3d86b216777c11ea195a021b8/docs/plugins/sdk-provider-plugins/voice-and-audio.md#L68-L119)

Core starts `connect()` after creating a relay and emits `ready` when it resolves. `onPartial` maps to a `partial` event / `transcript.delta`; `onTranscript` maps to final `transcript` / `transcript.done`; `onError` closes the relay. Stop invokes provider `close()` and keeps the relay registered for a **5-second provider final-drain window**, allowing asynchronous finals; the browser itself waits up to **10 seconds** for late finals. Therefore `close()` must trigger a bounded final flush promptly and only once. [Relay start/callbacks](https://github.com/openclaw/openclaw/blob/d30287734dee7ab3d86b216777c11ea195a021b8/src/gateway/talk/transcription-relay.ts#L281-L427) · [Relay close/drain](https://github.com/openclaw/openclaw/blob/d30287734dee7ab3d86b216777c11ea195a021b8/src/gateway/talk/transcription-relay.ts#L475-L505) · [Browser late-final wait](https://github.com/openclaw/openclaw/blob/d30287734dee7ab3d86b216777c11ea195a021b8/ui/src/pages/chat/composer-dictation.ts#L13-L22) · [Browser drain logic](https://github.com/openclaw/openclaw/blob/d30287734dee7ab3d86b216777c11ea195a021b8/ui/src/pages/chat/composer-dictation.ts#L354-L385)

## Audio contract and quality ceiling

The stock browser composer requests an 8 kHz `AudioContext`, encodes samples as **G.711 μ-law**, calls `talk.session.appendAudio`, and rejects a different format from the Gateway. The relay enforces/returns `g711_ulaw` at `8000` Hz and forwards decoded base64 bytes to provider `sendAudio`. Thus the plugin must decode μ-law to PCM and resample to the rate expected by Faster-Whisper (typically 16 kHz). Resampling cannot restore high-frequency speech already lost at 8 kHz: this is a source-imposed quality ceiling for the stock composer (inference). [Browser capture/session](https://github.com/openclaw/openclaw/blob/d30287734dee7ab3d86b216777c11ea195a021b8/ui/src/pages/chat/composer-dictation.ts#L13-L21) · [Browser create](https://github.com/openclaw/openclaw/blob/d30287734dee7ab3d86b216777c11ea195a021b8/ui/src/pages/chat/composer-dictation.ts#L139-L181) · [Browser append](https://github.com/openclaw/openclaw/blob/d30287734dee7ab3d86b216777c11ea195a021b8/ui/src/pages/chat/composer-dictation.ts#L250-L266) · [Relay constants/guard](https://github.com/openclaw/openclaw/blob/d30287734dee7ab3d86b216777c11ea195a021b8/src/gateway/talk/transcription-relay.ts#L38-L50) · [Relay send](https://github.com/openclaw/openclaw/blob/d30287734dee7ab3d86b216777c11ea195a021b8/src/gateway/talk/transcription-relay.ts#L439-L461)

Relay bounds: 30-minute session TTL, at most 2 transcription sessions per Gateway connection and 64 globally, and at most 512 KiB per base64 audio frame. Connection cleanup and expiry close provider sessions. Plugin should itself bound buffering, inference concurrency, and worker lifetime; core bounds are not a substitute (recommendation). [Relay limits/lifecycle](https://github.com/openclaw/openclaw/blob/d30287734dee7ab3d86b216777c11ea195a021b8/src/gateway/talk/transcription-relay.ts#L38-L50) · [Connection cleanup](https://github.com/openclaw/openclaw/blob/d30287734dee7ab3d86b216777c11ea195a021b8/src/gateway/talk/transcription-relay.ts#L216-L244)

## Existing UX: do not rebuild

The browser composer already chooses a saved microphone, handles capture/error states, displays partial and final transcript, and inserts committed text into the editable composer. It does not implicitly send that text to the agent. Different microphones are a browser input setting, not a provider API parameter; test each microphone end-to-end. [Mic/session handling](https://github.com/openclaw/openclaw/blob/d30287734dee7ab3d86b216777c11ea195a021b8/ui/src/pages/chat/composer-dictation.ts#L139-L181) · [Event/transcript handling](https://github.com/openclaw/openclaw/blob/d30287734dee7ab3d86b216777c11ea195a021b8/ui/src/pages/chat/composer-dictation.ts#L273-L326) · [Commit path](https://github.com/openclaw/openclaw/blob/d30287734dee7ab3d86b216777c11ea195a021b8/ui/src/pages/chat/composer-dictation.ts#L666-L680) · [Microphone selection behavior](https://github.com/openclaw/openclaw/blob/d30287734dee7ab3d86b216777c11ea195a021b8/docs/web/control-ui/chat.md#L286)

## Configuration and discovery caveat

For transcription-only Talk, `buildTalkTranscriptionConfig()` currently reads the default provider and provider options from `plugins.entries.voice-call.config.streaming.provider` and `.streaming.providers.<id>`. Browser composer does **not** pass a provider/model override to `talk.session.create`. Explicit provider selection is authoritative; absent selection, provider `autoSelectOrder`/registry order governs. This is surprising but is the actual v2026.9.6 code path. Do not assume `talk.transcription.*` is an accepted config key. [Config source](https://github.com/openclaw/openclaw/blob/d30287734dee7ab3d86b216777c11ea195a021b8/src/gateway/talk/session-config.ts#L126-L165) · [Build/resolve](https://github.com/openclaw/openclaw/blob/d30287734dee7ab3d86b216777c11ea195a021b8/src/gateway/talk/session-config.ts#L304-L378) · [Browser create](https://github.com/openclaw/openclaw/blob/d30287734dee7ab3d86b216777c11ea195a021b8/ui/src/pages/chat/composer-dictation.ts#L162-L168)

`voice-call` has a schema for `streaming.provider`/`streaming.providers`; whether that section is usable without enabling the voice-call plugin on this host must be checked in an isolated runtime before live configuration. Do not enable telephony streaming merely for dictation. [Voice-call manifest labels](https://github.com/openclaw/openclaw/blob/d30287734dee7ab3d86b216777c11ea195a021b8/extensions/voice-call/openclaw.plugin.json#L122-L136)

Provider choice/model can appear in `talk.catalog`; the documented precedence for model is explicit session override, configured provider model, `agents.defaults.voiceModel`, then provider default. [Talk catalog model guidance](https://github.com/openclaw/openclaw/blob/d30287734dee7ab3d86b216777c11ea195a021b8/docs/nodes/talk/realtime-sessions.md#L139-L144)

## Package, install, reload, and tests

An external native plugin should ship built JS entrypoint(s), `package.json` with `openclaw.extensions` (and runtime entry if needed), and `openclaw.plugin.json` with matching ID, inline `configSchema` even if empty, and `contracts.realtimeTranscriptionProviders: ["<provider-id>"]`. Use `definePluginEntry` from `openclaw/plugin-sdk/plugin-entry` for a non-channel plugin. `openclaw.compat.pluginApi` is the enforced API floor. Do **not** use the Codex `.codex-plugin/plugin.json` format. [Entry helper](https://github.com/openclaw/openclaw/blob/d30287734dee7ab3d86b216777c11ea195a021b8/docs/plugins/sdk-entrypoints/define-plugin-entry.md#L13-L56) · [Manifest required fields](https://github.com/openclaw/openclaw/blob/d30287734dee7ab3d86b216777c11ea195a021b8/docs/plugins/manifest.md#L215-L235) · [Capability contract](https://github.com/openclaw/openclaw/blob/d30287734dee7ab3d86b216777c11ea195a021b8/docs/plugins/manifest/capabilities.md#L27-L69) · [Package fields](https://github.com/openclaw/openclaw/blob/d30287734dee7ab3d86b216777c11ea195a021b8/docs/plugins/manifest/package-json.md#L25-L65)

The generic `--type provider` scaffold builds a model provider, not a transcription-only provider; adapt rather than retain its model/API-key boilerplate. `openclaw plugins build/validate` generated-metadata flow is explicitly for the tool scaffold, not the generic provider scaffold. Use package build/test plus the actual plugin validator and isolated runtime smoke. [Authoring/scaffold](https://github.com/openclaw/openclaw/blob/d30287734dee7ab3d86b216777c11ea195a021b8/docs/cli/plugins/authoring.md#L13-L82)

For local development, `openclaw plugins install -l <path>` links rather than copies. Installing an arbitrary local source is a trust/capability-consent action and can apply to a running Gateway; do this only at the approved activation stage. `openclaw plugins reload <id>` updates a discovered plugin **without restarting the Gateway**, preserving enabled state, but waits up to 60 seconds for in-flight work and may report old native modules still loaded. Therefore a persistent Faster-Whisper worker needs explicit teardown/cleanup on reload, and a fresh process may still be prudent when native GPU libraries persist (inference). [Install semantics](https://github.com/openclaw/openclaw/blob/d30287734dee7ab3d86b216777c11ea195a021b8/docs/cli/plugins/install.md#L12-L65) · [Reload semantics](https://github.com/openclaw/openclaw/blob/d30287734dee7ab3d86b216777c11ea195a021b8/docs/cli/plugins/uninstall-and-update.md#L127-L158)

This is a test plan, not observed test completion. ## Implementation verification correction (P1 review)

The initial UX summary was incomplete. `ComposerDictationController.stop()` at
`composer-dictation.ts:659–700` commits any nonempty `transcriptSnapshot()` before
calling `finish()`, and ignores an async final when that immediate commit occurs.
Only an empty snapshot takes `finish(true)` and the late-final accumulator. Thus
streaming partials plus reliable final-tail replacement cannot both be achieved
through the current provider contract alone. The implementation now sends final
callbacks only; internal speculative decoding never emits previews. The actual
stock controller/session regression reproduces the old bug and proves corrected
late insertion. See `docs/STOCK-COMPOSER.md` for the unavoidable five-second
Stop-to-insertion delay and rejected workarounds.

The actual native loader/selection smoke also verifies that
`agents.defaults.voiceModel: "faster-whisper/medium"` selects this transcription
provider without a voice-call entry. The legacy explicit streaming-provider
setting still wins when present; no live settings were inspected or changed.
