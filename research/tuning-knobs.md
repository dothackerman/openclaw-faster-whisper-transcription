# Dictation transcription tuning: evidence and experiment plan

Research date: 2026-09-29. Scope: local Faster-Whisper/CTranslate2 transcription on an RTX 3060 Laptop GPU with 6 GB VRAM, from OpenClaw browser dictation audio reported as 8 kHz G.711 μ-law; several microphones; English, German, and Swiss German. **No measured results are claimed here.** These are controls and hypotheses to test on OG's actual clips. All URLs below are upstream project documentation/source, OpenAI's Whisper source, or the relevant IETF specification.

## What is established

| Control / fact | Supported finding | Implication for this use case |
| --- | --- | --- |
| Audio decode | Faster-Whisper's file decoder converts to mono float32 at 16 kHz; NumPy waveform input bypasses that decoder. [Faster-Whisper audio source](https://github.com/SYSTRAN/faster-whisper/blob/master/faster_whisper/audio.py), [OpenAI Whisper audio source](https://github.com/openai/whisper/blob/main/whisper/audio.py) | For raw G.711 bytes, decode μ-law and resample 8→16 kHz **exactly once** before passing a float32 waveform; check sample count, clipping and duration. Merely labelling 8 kHz samples as 16 kHz will produce wrong speed/pitch. Resampling cannot recreate lost high-frequency content (signal-processing inference). |
| Input bandwidth | RTP PCMU is G.711 μ-law; the standard static PCMU payload uses 8 kHz. [RFC 3551 §4.5.14 and payload table](https://www.rfc-editor.org/rfc/rfc3551.html#section-4.5.14) | Preserve the original encoded and decoded samples in the *local* test set. If a higher-fidelity capture path becomes available, compare it before investing in expensive decoding settings. Do not assume every browser/mic path actually has the same source fidelity. |
| Model choice | Whisper lists multilingual `small` (~2 GB), `medium` (~5 GB), and `turbo` (~6 GB) approximate **PyTorch** VRAM figures, and warns that published relative speeds are A100/English measurements. Faster-Whisper supports `large-v3-turbo`/`turbo` and quantized execution. [Whisper models](https://github.com/openai/whisper#available-models-and-languages), [Faster-Whisper model constructor](https://github.com/SYSTRAN/faster-whisper/blob/master/faster_whisper/transcribe.py) | Start with the previously planned multilingual `medium`, but also benchmark `small` and `large-v3-turbo`. Do **not** infer that the ~6 GB PyTorch `turbo` estimate fits with all desktop GPU consumers, or that `medium` beats turbo in quality/speed on this hardware. `.en` models cannot cover German; `task="transcribe"`, not `translate`, is required. |
| Precision | CTranslate2 supports `float16` and `int8_float16` on modern NVIDIA GPUs; `auto` selects a supported fast type. Actual support can be queried via `ctranslate2.get_supported_compute_types`, and CT2 may convert unsupported storage types on load. [CTranslate2 quantization](https://opennmt.net/CTranslate2/quantization.html), [Faster-Whisper GPU examples](https://github.com/SYSTRAN/faster-whisper#gpu) | Compare `float16` with `int8_float16` on *this* GPU. Record actual VRAM, speed, and transcription differences; no blanket claim that INT8 is always faster or lossless. Leave VRAM headroom for the display and other processes. |
| Beam / fallback | Faster-Whisper exposes `beam_size` (default 5), temperature fallback, compression/log-probability/no-speech thresholds, and `best_of` for nonzero-temperature sampling. [Faster-Whisper `transcribe` signature/docstring](https://github.com/SYSTRAN/faster-whisper/blob/master/faster_whisper/transcribe.py) | Beam 1/3/5 is a central quality-latency test. Keep fallback thresholds at defaults until baseline; log how often fallback happens, since it may add unpredictable delay. `best_of` is not a beam-search knob at temperature 0. |
| Language | With `language=None`, Faster-Whisper detects language from the first window; `multilingual=True` enables language detection per window. It exposes `language_detection_segments` and `language_detection_threshold`. [Faster-Whisper source](https://github.com/SYSTRAN/faster-whisper/blob/master/faster_whisper/transcribe.py) | Compare automatic detection with explicit `de`/`en` where the intended language is known. For within-utterance switching, compare `multilingual=True` and inspect whether the result transcribes rather than translates or drops words. Swiss German has no separate Whisper language code in the upstream list: test it as `de` and with auto detection; do not claim guaranteed dialect support. [Whisper language list](https://github.com/openai/whisper/blob/main/whisper/tokenizer.py) |
| VAD | Faster-Whisper integrates Silero VAD. Standard `WhisperModel.transcribe` defaults `vad_filter=False`; batched pipeline defaults `True`, so these entry points are **not equivalent by default**. Current VAD source defines `threshold=0.5`, `min_silence_duration_ms=2000`, `speech_pad_ms=400` in `VadOptions`; the batched path may override settings. [Faster-Whisper transcribe source](https://github.com/SYSTRAN/faster-whisper/blob/master/faster_whisper/transcribe.py), [VAD options/source](https://github.com/SYSTRAN/faster-whisper/blob/master/faster_whisper/vad.py) | Test endpointing/no-speech suppression without cutting word beginnings/endings. Record exact entry point and explicit VAD options. For short dictation, VAD may add overhead or suppress quiet speech; that is an experimental question. |
| Prompts/context | `initial_prompt` and `hotwords` are supported. `hotwords` has no effect when `prefix` is set. Previous-text conditioning can improve continuity but may increase repetition/failure-loop risk. [Faster-Whisper source](https://github.com/SYSTRAN/faster-whisper/blob/master/faster_whisper/transcribe.py), [OpenAI Whisper transcribe source](https://github.com/openai/whisper/blob/main/whisper/transcribe.py) | Test a short, fixed glossary of OG's actual names/technical terms only after clean baseline. Do not stuff a long instruction prompt or use another dictation's text without measuring contamination. For independent utterances, compare `condition_on_previous_text=False` to default. |
| Timestamps / batching | `word_timestamps` adds alignment processing. Batched inference uses separate settings and increases memory demand; Faster-Whisper's published large-v2 GPU benchmark shows more VRAM with batch 8, on hardware/workloads unlike OG's. [Faster-Whisper README benchmark](https://github.com/SYSTRAN/faster-whisper#benchmark), [source](https://github.com/SYSTRAN/faster-whisper/blob/master/faster_whisper/transcribe.py) | Skip word-level timestamps unless OpenClaw's integration needs them. Single-user dictation favors low queueing/tail latency over throughput; start unbatched (`WhisperModel.transcribe`). |

## Hypotheses requiring local measurement

1. `large-v3-turbo` with INT8/FP16 may deliver a better quality/latency/VRAM Pareto point than `medium`, despite the roadmap's initial `medium` choice. Upstream speed and VRAM values are **not** RTX 3060 Laptop 6 GB measurements. The OpenAI model announcement says turbo has four decoder layers versus 32 for large-v3, with some accuracy degradation by language; Swiss German and 8 kHz G.711 are not separately established there. [OpenAI turbo announcement](https://github.com/openai/whisper/discussions/2363)
2. A lower beam may cut decoding time without perceptible accuracy loss on clean speech, but may worsen names, dialect, or noisy microphones. The effect must be measured per subset.
3. Short partial windows may be unstable because Whisper was designed around up-to-30-second windows; overlapping/re-decoding audio may improve context at additional GPU cost. Evaluate first visible text, edit churn and final accuracy, not only final time. [Whisper audio constants](https://github.com/openai/whisper/blob/main/whisper/audio.py)
4. VAD may reduce hallucinations/load on silence, but its thresholds and padding can delete quiet syllables. Evaluate false cuts explicitly. The source documents each threshold, but no default is proven best for this microphone mix. [Faster-Whisper VAD source](https://github.com/SYSTRAN/faster-whisper/blob/master/faster_whisper/vad.py)
5. Mic placement, room noise, gain, echo cancellation and source bandwidth may dominate decoder tweaks. Compare microphones *at matched utterances*, preserving the actual browser/OpenClaw capture path. Do not normalize or denoise by default: any preprocessing must be an A/B condition on original audio, because it can damage consonants or proper names.

## Experiment contract

Use only consented, local test recordings. Build a small, versioned manifest (without publishing private audio) with at least: mic ID, codec/source sample rate, language/dialect, utterance class, expected words, noise condition, duration, and reference transcript. Include silence, quiet speech, names, technical terms, numbers, punctuation, accented English, Standard German, Swiss German, and German↔English switching. Use multiple speakers only if relevant. **Keep a held-out set** to prevent tuning to the handful of examples.

For every run, record immutable audio hash, model ID/revision, Faster-Whisper/CTranslate2/CUDA versions, GPU identity and concurrent VRAM use, compute type, all decoding/VAD/window options, warm/cold status, output transcript, detected language/probability, per-utterance time to first stable partial and final, real-time factor, peak VRAM, GPU utilization/power where available, CPU/RAM, and transcription errors. Score final WER and character error rate after a *documented* normalization; separately count deletions, dialect substitutions, proper-name errors, hallucinations on silence, truncation, code-switch errors, and user-visible partial rewrites. Report median and p95 latency by clip length and mic; do not combine cold model-load time with warm inference.

Change **one axis at a time** after baseline. Repeat each candidate at least three warm runs when measuring latency; randomize run order to reduce temperature/load bias. A candidate wins only if it improves a predeclared quality/latency/VRAM objective on held-out clips, not because it sounds good on one sample. Pin the exact winning settings and retain a baseline to detect regression.

## Prioritized matrix

| Order | A/B conditions | Primary question / decision |
| --- | --- | --- |
| 0 — correctness | Known 8 kHz μ-law test vector → decode → 16 kHz float32; compare sample duration, amplitude, and a round-trip/known waveform. Capture-path inventory per mic. | Eliminate format bugs before model comparisons. Verify whether incoming audio is truly 8 kHz G.711 for every path. |
| 1 — baseline | `medium`, CUDA `float16`, unbatched, `task="transcribe"`, `beam_size=5`, default fallback, `language=None`, `vad_filter=False`, no prompt; final-on-stop. | Establish quality and peak VRAM on actual dictation. Record whether this fits safely while desktop/GPU users are active. |
| 2 — model/precision | `small`, `medium`, `large-v3-turbo` × `float16`/`int8_float16` where runtime-supported; hold all other settings. | Find Pareto frontier; reject combinations that OOM, slow interactive latency, or lose dialect/proper-name accuracy. Avoid full Cartesian expansion if a model clearly fails. |
| 3 — decoding | Winner(s) × `beam_size=1,3,5`; fixed `temperature=0` first, then default fallback policy. | Determine whether wider search helps actual error classes enough to justify latency and GPU work. Count fallback retries. |
| 4 — language | Auto vs explicit `de`/`en` on known-language clips; `multilingual=False/True` for switching clips; optionally detection segments 1 vs 2 if clips are long enough. | Prevent wrong-language output, translation, or words lost at switch. Do not expose language selection UI unless evidence calls for it. |
| 5 — endpoint/partials | Final-only vs incremental 2/4/6-second windows (implementation hypothesis), with/without a short overlap; VAD off vs explicit threshold/pad/silence settings. | Optimize time to first *stable* preview and final without chopped words, repeated text, or excessive re-decodes. Chunk durations are proposals, not upstream recommended values. |
| 6 — vocabulary/context | No prompt vs short static glossary; `hotwords` vs `initial_prompt`; previous-text conditioning on/off only for multi-window utterances. | Fix recurring proper-name/technical-term errors without hallucination or contamination. |
| 7 — audio handling | Per mic: raw decoded signal baseline vs controlled gain/noise-suppression/echo-cancellation variants if available; compare G.711 path with any supported higher-fidelity path. | Address source-quality bottlenecks before adding model complexity. Never silently change the user's selected mic. |

### Initial implementation defaults versus tuning switches

The defaults above are **baseline choices, not claims of optimum**. Keep the implementation's normal path simple: decode the supplied audio correctly; maintain one warm model instance; transcribe locally; emit partials only if the integration contract supports them; deliver final text for editable review, never auto-send. Put experiment settings in a versioned local profile or test harness, not a UI full of decoding controls. The final profile must be chosen from measurements on OG's actual microphones and spoken material.
