# Long-duration stock-browser dictation contract (OpenClaw 2026.9.6)

Observed 2026-09-29 in the locally active OpenClaw 2026.9.6 source checkout at commit [`d30287734dee7ab3d86b216777c11ea195a021b8`](https://github.com/openclaw/openclaw/tree/d30287734dee7ab3d86b216777c11ea195a021b8); `openclaw --version` reports 2026.9.6. This is source analysis, not a live microphone test. User requirement: no practical recording cap; if a technical ceiling is unavoidable, 60 minutes; use 20 seconds for rapid tests and five minutes for end-to-end acceptance.

## Decisive host limits

| Constraint | Source-observed behavior | Scope |
| --- | --- | --- |
| Relay lifetime | `TRANSCRIPTION_SESSION_TTL_MS = 30 * 60 * 1000`; timer starts at creation, and append/close ownership checks reject expired sessions. No config or provider-supplied TTL is read. [Relay constants/create/timer](https://github.com/openclaw/openclaw/blob/d30287734dee7ab3d86b216777c11ea195a021b8/src/gateway/talk/transcription-relay.ts#L34-L43), [expiry check](https://github.com/openclaw/openclaw/blob/d30287734dee7ab3d86b216777c11ea195a021b8/src/gateway/talk/relay-session-lifecycle.ts#L74-L92) | **Hard stock-host 30-minute ceiling**. Raising plugin `maxAudioSeconds` cannot extend it. Session starts after mic opens, so usable capture time is slightly less. |
| Stop-to-final | `talk.session.close` calls relay stop; relay calls provider `close()` and keeps the session for 5 seconds, then removes it. Provider finals after removal are ignored. Browser late-final listener waits up to 10 seconds but resolves on relay close; 10 seconds is not provider inference time. [Relay stop](https://github.com/openclaw/openclaw/blob/d30287734dee7ab3d86b216777c11ea195a021b8/src/gateway/talk/transcription-relay.ts#L465-L505), [late-final wait](https://github.com/openclaw/openclaw/blob/d30287734dee7ab3d86b216777c11ea195a021b8/ui/src/pages/chat/composer-dictation.ts#L354-L384) | **Hard stock-host finalization budget** of <5 seconds after Stop. Long recordings must be incrementally decoded during capture; a single five-minute or hour-long decode at Stop is not a viable contract. |
| Browser preview/final | Stop snapshots all finals and any current partial *before* calling `finish`; a nonempty snapshot commits immediately, then late final is ignored. Empty snapshot takes the late-final path and inserts the completed transcript into the editable composer. [Stop controller](https://github.com/openclaw/openclaw/blob/d30287734dee7ab3d86b216777c11ea195a021b8/ui/src/pages/chat/composer-dictation.ts#L659-L707), [snapshot/partials](https://github.com/openclaw/openclaw/blob/d30287734dee7ab3d86b216777c11ea195a021b8/ui/src/pages/chat/composer-dictation.ts#L270-L325) | **Hard stock-UI behavior**: provider-sent partials or early finals can make the final tail disappear. For correct final-only insertion, keep intermediate transcript internal to the plugin until Stop. Host UI change is needed for reliable live editable preview plus final replacement. |
| Per-frame size | Browser sends 8 kHz G.711 μ-law; relay requires that format and caps *each base64 frame* at 512 KiB, not total session audio. Browser's 4096-sample `ScriptProcessor` callback yields nominal 0.512-second / 4096-byte audio frames (~5464 base64 chars), far below that cap. [Browser format](https://github.com/openclaw/openclaw/blob/d30287734dee7ab3d86b216777c11ea195a021b8/ui/src/pages/chat/composer-dictation.ts#L14-L20), [audio pump](https://github.com/openclaw/openclaw/blob/d30287734dee7ab3d86b216777c11ea195a021b8/ui/src/pages/chat/talk/audio.ts#L75-L96), [relay cap/format](https://github.com/openclaw/openclaw/blob/d30287734dee7ab3d86b216777c11ea195a021b8/src/gateway/talk/transcription-relay.ts#L38-L43), [send](https://github.com/openclaw/openclaw/blob/d30287734dee7ab3d86b216777c11ea195a021b8/src/gateway/talk/transcription-relay.ts#L439-L463) | Not a duration cap; no whole-recording upload occurs. 5 minutes is ~2.4 MB and ~586 nominal frames; 60 minutes ~28.8 MB and ~7031 frames before protocol overhead. |
| Browser startup buffer | Audio arriving before session creation is accepted only up to 10 seconds, then silently dropped; after creation, queued audio is sent in sequential RPCs. [Capture/start](https://github.com/openclaw/openclaw/blob/d30287734dee7ab3d86b216777c11ea195a021b8/ui/src/pages/chat/composer-dictation.ts#L142-L185), [buffer/queue](https://github.com/openclaw/openclaw/blob/d30287734dee7ab3d86b216777c11ea195a021b8/ui/src/pages/chat/composer-dictation.ts#L230-L268) | Startup correctness risk, not a long-session cap. |
| Backpressure | `appendChain` serializes each `talk.session.appendAudio` RPC; there is no browser queue-length or queue-age bound after creation. Each Gateway append synchronously calls provider `sendAudio`, then acknowledges. The public provider method is synchronous and has no backpressure return. [Browser queue](https://github.com/openclaw/openclaw/blob/d30287734dee7ab3d86b216777c11ea195a021b8/ui/src/pages/chat/composer-dictation.ts#L255-L268), [Gateway handler](https://github.com/openclaw/openclaw/blob/d30287734dee7ab3d86b216777c11ea195a021b8/src/gateway/talk/handlers/session.ts#L458-L498), [provider interface](https://github.com/openclaw/openclaw/blob/d30287734dee7ab3d86b216777c11ea195a021b8/src/realtime-transcription/provider-types.ts#L20-L40) | Plugin must admit/reject audio promptly and bound *its* inference queue/memory. A slow RPC or overloaded worker can still grow the browser's pending chain; true flow control needs host changes. Avoid silently discarding audio. |

The relay also limits active sessions to two per connection and 64 globally, and closes sessions on connection disconnect. Browser blur, hidden tab, Escape, and some pointer-cancel paths stop/cancel capture. These are operational risks for five-minute and longer recordings, not configurable plugin limits. [Relay limits/connection cleanup](https://github.com/openclaw/openclaw/blob/d30287734dee7ab3d86b216777c11ea195a021b8/src/gateway/talk/transcription-relay.ts#L34-L40), [disconnect cleanup](https://github.com/openclaw/openclaw/blob/d30287734dee7ab3d86b216777c11ea195a021b8/src/gateway/talk/transcription-relay.ts#L216-L235), [browser cancellation](https://github.com/openclaw/openclaw/blob/d30287734dee7ab3d86b216777c11ea195a021b8/ui/src/pages/chat/composer-dictation.ts#L573-L598).

## Design consequence

**Five minutes is architecturally possible within the stock relay, but unproven. Sixty minutes is impossible through this plugin's public contract on the active stock host:** the browser owns one session ID and offers no relay renewal/rotation hook; the relay expires it at 30 minutes. A 60-minute technical ceiling would require an upstream/local OpenClaw host change to the TTL (plus qualification of browser queue/recovery), or a supported host-side session rollover design. It is not responsible to advertise a 60-minute ceiling merely by lifting the plugin schema limit. [Browser session ownership](https://github.com/openclaw/openclaw/blob/d30287734dee7ab3d86b216777c11ea195a021b8/ui/src/pages/chat/composer-dictation.ts#L162-L185), [relay TTL](https://github.com/openclaw/openclaw/blob/d30287734dee7ab3d86b216777c11ea195a021b8/src/gateway/talk/transcription-relay.ts#L258-L270).

Idiomatic provider architecture: `registerRealtimeTranscriptionProvider`, one bounded session implementing `connect/sendAudio/close/isConnected`. Decode incoming μ-law frames, run serial bounded-window inference while capture continues, retain a short overlapping undecoded tail, and on `close()` finish only that tail inside the <5-second relay window. Keep provisional text internal; emit final transcript(s) only after Stop (or after a host UI fix). Bound undecoded audio, work queue, transcript size, worker lifecycle, and concurrent sessions; on overload, fail explicitly rather than inventing missing words. A fixed rolling buffer/window is preferable to accumulating an entire long waveform. The exact windowing/overlap/deduplication policy is an empirical quality decision, not guaranteed by this SDK. [Provider callbacks/interface](https://github.com/openclaw/openclaw/blob/d30287734dee7ab3d86b216777c11ea195a021b8/src/realtime-transcription/provider-types.ts#L20-L40), [relay callbacks](https://github.com/openclaw/openclaw/blob/d30287734dee7ab3d86b216777c11ea195a021b8/src/gateway/talk/transcription-relay.ts#L290-L355).

Acceptance: use 20-second clips for fast latency/quality iteration; run at least one continuous five-minute real-microphone end-to-end test through the stock composer, checking no omissions/duplications at chunk boundaries, bounded lag/memory, all text present and editable after Stop, and no auto-send. The five-minute test must include the complete browser→Gateway→provider→browser path, not merely a Python worker decode. Separately validate overload, interrupted connection/tab, and relay-expiry behavior before claiming anything near the host's 30-minute ceiling. A 60-minute acceptance test is blocked by the host TTL until the host is changed. This is a proposed qualification plan, not an observed pass.
