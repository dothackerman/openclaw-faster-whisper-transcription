# Long-duration dictation: quality and latency design note

Status: historical design input, 2026-09-29. RC2 subsequently implemented bounded-window decoding; see the [implementation plan](../docs/LONG-DURATION-PLAN.md) and [measured results](LONG-DURATION-RESULTS.md) for the released state. This note does not establish live-microphone quality or 60-minute readiness.

## Requirement and observed baseline

OG wants uninterrupted dictation, with no ordinary duration cap; if a technical maximum is necessary it should be 60 minutes. Use 20-second recordings for fast iteration and a five-minute whole-path test for end-to-end confidence. A 60-minute limit is a safety ceiling, **not** permission to buffer or decode an hour as one request.

The stock composer supplies 8 kHz G.711 μ-law bytes; the worker converts them to 16 kHz float32. Upsampling cannot recover frequencies absent from the 8 kHz capture. **Before RC2**, the provider held all audio, optionally retranscribed the whole growing buffer, and on Stop decoded the full remainder. That prototype defaulted to 15 seconds with a 120-second hard transport ceiling. The [historical duration screen](../docs/DURATION-DECISION.md) found 9/24 timeouts on repeated synthetic English at 30–120 seconds under both medium/float16/beam-5 and beam-1; some German outputs were suspiciously short. This was a counterexample to the **old full-buffer architecture**, not a measured result for the later bounded-window implementation or representative WER. The stock relay's five-second drain still means raising the plugin timeout is not a solution. RC2 instead uses 16-second bounded windows, a 32-second rolling queue, a 60-minute plugin safety ceiling, and one final result under its 4.5-second deadline; the stock host still expires sessions at 30 minutes. [Current provider](../src/provider.ts), [worker](../python/worker.py), [limits](../src/limits.ts), [stock integration contract](openclaw-plugin-contract.md).

## Design criteria used for the bounded-window prototype

1. **Capture and accounting.** Append 8 kHz μ-law frames in original sample order; assign monotonically increasing sample offsets and verify no gap/duplicate at ingress. Keep only a bounded uncommitted audio ring plus a small overlap/context tail, not all history. Keep committed text separately, with a bounded transcript size or explicit failure when capacity is exhausted. For a 60-minute recording the raw input would be 28.8 MB, but avoiding that allocation is primarily about predictable queueing, requests, and final latency, not raw byte size alone.
2. **Choose endpoints.** Prefer a detected pause as a candidate boundary, but enforce a maximum speech-window length below Whisper's roughly 30-second processing window. If speech is continuous, force a boundary with overlap. Initial window/overlap values are **hypotheses** (e.g. 15–20 seconds and 1–2 seconds) to sweep on recordings, not supported defaults or quality guarantees. Never discard quiet audio solely because VAD calls it silence; retain enough padding and account for every input sample. Faster-Whisper v1.2.1's VAD implementation has configurable threshold, minimum silence and speech padding; a forced maximum can cut aggressively when no suitable silence exists. [Whisper audio constants](https://github.com/openai/whisper/blob/main/whisper/audio.py), [Faster-Whisper v1.2.1 VAD](https://github.com/SYSTRAN/faster-whisper/blob/v1.2.1/faster_whisper/vad.py).
3. **Decode and commit internally.** Run a single unbatched CUDA inference lane. Decode only a bounded window, not every prefix of the five-minute recording. Keep a provisional right-edge region uncommitted; compare adjacent overlapping decodes and commit stable words/tokens only when the later decode confirms them. Retain provenance as audio offsets plus the model's segment timestamps. At a forced split, use overlapping audio and time-aware/token-alignment deduplication, with a deterministic tie rule; naive text concatenation doubles words and naive string suffix matching can delete genuine repeated words. Segment timestamps are approximate, so boundary tests and manual review are essential. Consider word timestamps only if segment-level alignment fails—their alignment pass adds work. Send no interim transcript to the current stock composer: its Stop path may commit the partial and ignore a later corrected final. [Faster-Whisper v1.2.1 transcribe API/source](https://github.com/SYSTRAN/faster-whisper/blob/v1.2.1/faster_whisper/transcribe.py), [stock composer note](../docs/STOCK-COMPOSER.md).
4. **Backpressure.** Coalesce speculative work and never build an unbounded decode queue. Track `captured_end`, `decoded_end`, `committed_end`, decode wall time, and oldest unprocessed audio age. If inference persistently runs slower than capture, first skip obsolete speculative snapshots, not audio; when a bounded backlog threshold is exceeded, fail visibly and preserve already committed text if the contract permits. Do not pretend a 60-minute session is supported if sustained throughput cannot keep lag bounded. One user session and one worker avoid GPU contention from overlapping decodes; test background GPU load explicitly. [CTranslate2 performance tips](https://opennmt.net/CTranslate2/performance.html), [current serial worker](../src/worker.ts).
5. **Stop and flush.** On Stop, finish the in-flight bounded decode (or cancel obsolete speculative work if safe), decode only the remaining audio plus its overlap, reconcile once, and emit **one** final full transcript within the plugin's 4.5-second allowance. Measure from browser Stop to text visible in the editable composer, not just worker completion. Failure must be visible; never silently return a truncated transcript. This is the critical scheduling invariant: final work and any queued work must fit the fixed tail budget, independent of total dictation length. [OpenClaw integration contract](openclaw-plugin-contract.md), [current timeout path](../src/provider.ts).

## Accuracy hazards and tunable choices

| Concern | Testable choice and failure mode |
| --- | --- |
| Boundary words and repetition | Sweep endpoint padding/overlap and commit policy. Score deletions, duplicates, repeated phrases, and altered meaning specifically within ±3 seconds of every boundary. Include words split by forced cuts, silence cuts, and stop. Repeated proper names must not be deduplicated by text alone. |
| Language and code-switching | The current `language=None` detects language for a transcribe call; independent short chunks can alternate classifications and mistranscribe mixed German/English. Compare per-window auto detection, carried language with a confidence-based reset, and explicit multilingual behavior where supported. Preserve audio context at switches; do not lock an entire hour to its first language without evidence. Test Swiss German separately; neither general Whisper benchmark nor synthetic eSpeak establishes its accuracy. [Faster-Whisper source](https://github.com/SYSTRAN/faster-whisper/blob/v1.2.1/faster_whisper/transcribe.py). |
| Context/prompt drift | Compare bounded prior-text conditioning or a fixed technical-term glossary against no carry-over. Conditioning can improve continuity but can also propagate hallucination/repetition. Keep prompts short, scrub session state on new dictation, and inspect repeated speech. [Faster-Whisper source](https://github.com/SYSTRAN/faster-whisper/blob/v1.2.1/faster_whisper/transcribe.py). |
| Silence/VAD | Compare VAD off with explicit, recorded threshold/silence/padding settings. Count false cuts on quiet syllables, skipped short utterances, and false text on actual room silence. Exact digital-zero bypass in the current worker does not solve real microphone silence. Do not equate VAD speech boundaries with punctuation or sentence boundaries. [VAD source](https://github.com/SYSTRAN/faster-whisper/blob/v1.2.1/faster_whisper/vad.py). |
| Model, precision, beam | Start from the measured medium/float16/beam-5 baseline. Screen beam 1/3/5, `int8_float16`, and perhaps a smaller/more efficient multilingual model only with fixed audio and scoring. The beam-1 duration screen did **not** cure timeouts. CTranslate2 supports runtime compute-type queries and documents INT8/FP16 quantization/fallback; smaller weights or a lower beam do not prove better 3060 latency, WER, or power. Record actual runtime type and peak VRAM. [CTranslate2 quantization](https://opennmt.net/CTranslate2/quantization.html), [existing duration screen](../docs/DURATION-DECISION.md). |

Use `WhisperModel.transcribe` (unbatched) as the initial lane. Faster-Whisper's published throughput/VRAM tables are on different hardware and long files; batching might raise 6 GB VRAM pressure and end latency. Its returned segments are a generator, so timing must include consuming the generator, as the current worker does. [Faster-Whisper v1.2.1 README](https://github.com/SYSTRAN/faster-whisper/blob/v1.2.1/README.md).

## Objective benchmark and release gate

**Corpus.** Keep the existing synthetic public fixtures only for transport regression and rapid algorithm checks. Use consented, private, unlooped five-minute speech and 20-second clips captured through the stock browser at 8 kHz μ-law. Include OG's actual laptop microphone(s), normal and quiet speech, natural pauses, continuous speech forcing splits, English, Standard German, Swiss German, German↔English switches, technical names/numbers, silence, and an end word immediately before Stop. Human-create reference transcripts without viewing hypotheses. Freeze fixture hashes, references, normalization and a held-out set; do not publish private audio/text. [Experiment design](experiment-design.md).

**20-second rapid loop.** For every candidate run fixed 20-second clips and boundary adversaries repeatedly with exact same bytes. Validate sample continuity, bounded ring/queue, text commit/dedup, Stop flush, cancellation and error behavior. Score pooled and per-stratum WER/CER using the existing lexical normalization; separately count boundary deletions/duplications, hallucinated words during silence, code-switch errors, and meaningful substitutions. Log full output only in private artifacts. Collect warm Stop-to-final p50/p95 and timeout count; a single run does not qualify a profile. Use cold runs separately.

**Five-minute whole path.** Replay through the actual browser→Gateway→provider→composer path, then live-mic acceptance; do not substitute an offline Python file call. Run multiple fixed five-minute recordings and repeats with a loaded model. Verify the editable final transcript contains beginning, middle and last words, and no auto-send. Record per-window inference time and audio duration, queue/backlog age throughout, first stable internal commit, Stop-to-worker-final, and browser Stop-to-visible-final. The stock final result must arrive before the relay's five-second drain, with the plugin's 4.5-second deadline respected on every measured run. Mark any omission, duplicate, truncation, timeout or stale insertion as a failure, not merely a slower score. A five-minute pass is an end-to-end milestone, **not** proof of 60-minute durability: before advertising unlimited/60-minute recording, add a 60-minute soak with sustained bounded lag, memory, response/transcript capacity and repeated end-tail checks.

**GPU/system.** On the RTX 3060 Laptop 6 GB, record device/driver/versions, actual compute type, model hash, concurrent GPU processes, and AC/power/thermal state. Take a matched idle baseline; sample NVML/`nvidia-smi` through loading, capture, finalization and post-idle to report peak/incremental VRAM, utilization, power if available, CPU/RSS, and load/idle release. Compare candidates in randomized order with baseline reruns. Report WER/CER, p50/p95 and worst-case lag by language/mic/boundary class, not just aggregate speed. Do not infer gain from unmeasured knob changes or published GPU benchmarks. [NVIDIA SMI guide](https://docs.nvidia.com/deploy/nvidia-smi/index.html), [experiment protocol](experiment-design.md).

**Selection.** Keep only a candidate that completes the full path under the fixed tail deadline, has bounded backlog over five minutes, and is no worse in meaning-changing/boundary errors and important language strata than the baseline within measured variation. Human review of original audio and the editable final text can veto a nominal WER improvement. No benchmark result or quality claim is added by this design note.
